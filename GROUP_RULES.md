
# Code 16 Group Rules

## Teamwork
- Be on time with your daily update.
- Ask for help early. A blocker reported late costs the whole team.
- Respect each other's work. Give feedback on the code, not the person.

## Git workflow (from the capstone brief)
- Work on separate branches.
- Contributions go through pull requests.
- The person who opens a PR does not review and merge it.
- A PR must be reviewed before merging into main.
- Avoid unnecessary commits and PRs. Finish a task before asking for a merge.

## Code 16 rules
- Nobody pushes directly to main.
- One owner per task. Don't edit another member's block. Tell the owner or the team lead.
- Don't swap or hand over a task without telling Prince and Comfort first.
- Don't merge a PR with console errors or broken features.
- Use the shared CSS variables. No random colors or fonts.
- Check values in Figma yourself. Write your own code.

## Who does what
- Prince: team lead. Sets rules, final approval, merges.
- Comfort: assistant team lead. Project board, README, first review of every PR.

## Contribution
You are assessed as a group and on individual contribution. Work on your own branch, open your own PRs, send your daily update, and make sure your name is in the README next to your component.
